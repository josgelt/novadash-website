Build a Node.js monitoring service that watches a Paylogic resale page and sends Telegram alerts when tickets become available.

STACK
- Node.js 20+
- Playwright (chromium, headless) — page is JS-rendered
- node-cron
- dotenv
- No other runtime deps (use native fetch for Telegram API)

ENVIRONMENT VARIABLES (.env)
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
TARGET_URL=https://resale.paylogic.com/9710ed9ee7304fa29ece85758d0b61da/
CHECK_INTERVAL_CRON=* * * * *
NOTIFY_ON_SOLD_OUT=false

BEHAVIOR
1. On startup: run one immediate check, then schedule via node-cron using CHECK_INTERVAL_CRON.
2. Each check:
   - Launch headless Chromium, navigate to TARGET_URL, wait for networkidle.
   - Find the "Verfügbar" value: locate any element whose text contains "Verfügbar" (case-insensitive, German), then extract the associated numeric value from the nearest sibling/cell/adjacent node. Implement a robust selector that tries:
     a) table row where a cell contains "Verfügbar" → read other numeric cell
     b) any element with "Verfügbar" label → read adjacent number
   - Parse value to integer. If parsing fails, treat as error (not as 0).
   - Log: ISO timestamp, parsed value, change status.
3. State:
   - Persist last known integer value in ./state.json: { lastValue: number, lastCheck: ISO, consecutiveErrors: number }
   - Send Telegram alert when value transitions from 0 to >0.
   - If NOTIFY_ON_SOLD_OUT=true, also alert on transition from >0 to 0.
   - Do NOT alert if value unchanged.
   - Do NOT alert on first run — only record baseline.
4. Errors:
   - On scraping/parse error: increment consecutiveErrors, log, continue.
   - After 5 consecutive errors: send one Telegram error alert, reset counter to avoid spam.
   - Always close browser in finally block.

TELEGRAM MESSAGES
Available:
🎟️ Tickets verfügbar!
Anzahl: <value>
Link: <TARGET_URL>
Zeit: <ISO>

Sold out (optional):
❌ Wieder ausverkauft
Link: <TARGET_URL>

Error (after 5 fails):
⚠️ Monitor-Fehler seit <N> Checks
Letzter Fehler: <message>
